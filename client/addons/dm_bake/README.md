# The lighting bake

Areas get baked lighting (lightmaps) from Godot's LightmapGI. Godot bakes only inside its editor, on a graphics card, and in 4.7.2 a script
cannot start a bake (LightmapGI has no `bake()` method), so the bake runs on a team PC through a one-click helper and comes back as files.

## Pieces

- `client/addons/dm_bake/` (this plugin, enabled in `client/project.godot`): inert unless the editor starts with
  `-- --dm-bake=res://areas/graves.tscn[,...] [--dm-bake-result=<file>]`. Then, for each scene, it gives the scene's LightmapGI a fresh, empty
  `<scene>.lmbake` (without a data file the bake button opens a save dialog; an empty one also makes a failed bake visible, since a failed bake
  leaves the data untouched), switches the editor to its 3D view and presses the **Bake Lightmaps** button there (each scene without a lightmap image first gets a 4x4 stand-in `<scene>.exr` the editor imports, since Godot 4.7.2's first bake into an image it has never seen fails to load it back and shows a warning window) (found by its label, in English or the editor's language, waiting up to about 5 s for it to show; a bake that produced nothing is tried again, up to three times; the scene must open within about 10 s, and every scene that failed gets a second pass at the end), checks
  that lightmap textures came out, saves the scene, writes the result file (JSON: `ok`, Godot version, GPU, one row per scene with the time and
  any error) and quits (exit 1 when a scene failed).
- `server/death-muffin/test-channel/publish-bake-kit.sh <rev> [scene ...]`: builds the client at a committed revision in its own worktree, zips
  every tracked client file with Godot's import cache (the baking PC then uses the exact meshes and lightmap UVs this server built, and skips a
  long re-import) and the Windows combat core, and serves it with `latest.json` (revision, scenes, checksums, the official Godot 4.7.2 build and
  its SHA-512) at `https://muffindevelopment.com/death-muffin/bake-kit/`.
- `tools/rebuild/bake-helper/Bake-Lighting.bat`: the helper a team member double-clicks (one file; its PowerShell is inside). It downloads
  Godot 4.7.2 and the latest kit into `%LOCALAPPDATA%\DeathMuffin\bake` (checksums checked; Godot runs in self-contained mode, so it never touches
  another Godot install), imports, runs the editor with the plugin, and zips each scene's `.lmbake` and lightmap images (with their `.import`
  files) plus the result to the Desktop as `DeathMuffin-bake-<rev>.zip`, to drag into the Discord DM with Muffin Core.

## Bringing a bake in

The returned files are data next to the area scene (`client/areas/<area>.lmbake`, `<area>*.exr` and their imports). The area scene itself stays
generated by `client/tools/build_area.gd`, which points its LightmapGI at the data when it exists, so a bake never brings back an edited scene.
A bake belongs to the scene it was made from: when the converter changes an area's meshes or lights, that area is baked again. Until it is, the area has
no `<area>.lmbake` (the converter leaves its LightmapGI without data, and `client/tests/areas.gd` prints "the lighting bake is pending for ..." and lists the
areas); an old bake left next to a changed scene fails that test (a baked mesh is gone). So a converter change that touches meshes removes the area's `.lmbake`,
`.exr` and `.exr.import` in the same commit, and the next bake brings them back.

**Baking every pending area** (all twelve after the props' static batching, which put each 12 m cell's repeated props in one mesh with its own lightmap rects,
`client/README.md` "Areas"): a commit with the scenes goes into a kit, and the team's PC bakes them in about a minute.

```
server/death-muffin/test-channel/publish-bake-kit.sh <commit> res://areas/graves.tscn res://areas/chapterhouse.tscn res://areas/acre.tscn res://areas/alchemist_wing.tscn \
  res://areas/warren.tscn res://areas/ossuary.tscn res://areas/nave.tscn res://areas/coliseum.tscn res://areas/sanctum.tscn res://areas/cloister.tscn res://areas/pyre.tscn res://areas/fen.tscn
```

Then the helper (`Bake-Lighting.bat`) is double-clicked and the zip it leaves on the Desktop, `DeathMuffin-bake-<commit>.zip`, goes to the Discord DM with Muffin Core. Its
`<area>.lmbake`, `<area>.exr` and `<area>.exr.import` files go into `client/areas`, `bash tools/rebuild/build-areas.sh graves chapterhouse acre alchemist_wing warren ossuary nave
coliseum sanctum cloister pyre fen` points each LightmapGI at them (nothing else in the scenes changes), and `areas.gd` must pass with no area pending.

## What else the editor run changes

Opening the full editor does two things a headless import never does, both only in the kit's copy on the baking PC: it rewrites
`project.godot` in its own format (comments dropped, default values omitted) and its "used in 3D" detection switches some textures to VRAM
compression. Neither comes back: only the lightmap files do.

## Proven

The plugin was run end to end on the VPS with Mesa's software Vulkan driver (lavapipe) under a virtual display, on small test scenes: a
fresh scene, a re-bake, a scene with nothing to bake (fails with the reason) and a missing scene. Real areas are baked on a graphics card only:
on the VPS's software driver the editor alone needs about 4 minutes to open the client project, and a 5-minute capped bake of the Graves at the
lowest settings did not finish (2026-10-16).
