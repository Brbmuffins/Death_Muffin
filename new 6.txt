6. StartLimitIntervalSec
------------------------
Status: FIXED on 2026-07-03

Problem: StartLimitIntervalSec=0 was in [Service] section of
  /etc/systemd/system/crossworlds.service.
  systemd requires this key in [Unit]. Every daemon-reload was logging:
    "Unknown key name 'StartLimitIntervalSec' in section 'Service', ignoring."
  The key was silently ignored â€” the game server could hit the restart burst
  limit and stop recovering after crashes.

Fix: Moved StartLimitIntervalSec=0 from [Service] to [Unit].
  sudo systemctl daemon-reload  â€” completed cleanly.
  The running game server process was NOT restarted (not required for this change;
  the key only takes effect if the process crashes and needs to restart).

Current crossworlds.service:
  [Unit]
  Description=Crossworlds (BCE) - Game Server (Mirror/KCP :7777)
  After=network.target crossworlds-auth.service
