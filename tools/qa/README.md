# Running the whole suite

`node tools/qa/run-all.mjs [--port 5348] [--tree <dir>] [--only a,b] [--skip a,b] [--timeout 600] [--out <dir>] [--no-retry] [--list]`

Starts ONE fresh Vite on `127.0.0.1:<port>` from `<tree>` (default: the repo containing the script; long-lived dev servers go stale after big merges, with "GameRuntime not initialised"), warms it up, then runs every offline-preview smoke one at a time, each in its own process group with a timeout (a hung run is killed together with its Chromium, by PID, never `pkill`). Vite is stopped by PID at the end, on Ctrl-C and on errors. Use ports 5347-5349 on the shared VPS; the runner refuses a port that is already serving.

- Names are the script file name without `.cjs` (`acre-smoke`); `necro-audit` runs once per discipline (`necro-audit:Ossuary`, `DM_QA_DISC`) so each fits its budget; `--only necro-audit` expands to all four. `--list` prints what would run.
- `bot-playtest-smoke` is in the default list (about 2.5 game minutes per delay, 900 s budget). `perf-budget` and the pixel-metrics lib are not smokes, so `run-all` does not pick them up; run them by hand (below).
- Not in the default list (they need something else): `live-*`, `new-blood-live-smoke` (public site), `coop-ten-smoke` (isolated realtime server, see below), `offline-edition-smoke` (built PWA preview), `*-probe` (scratch MySQL), `easy-auto-balance` (a sample, not pass/fail), `first-hour-audit` and the image tools (report/art output).
- A failure is retried once: pass-on-retry is reported as **flaky**, fail-twice as **broken**. Exit code 1 only when something is broken.
- Output in `--out` (default `$TMPDIR/dm-qa-<stamp>`): `summary.json`, `summary.md` (matrix plus the log tail of every failed attempt), `logs/<script>.log`, `shots/<script>/` (each script gets its own `DM_QA_ARTIFACT_DIR`).
- The runner sets `DM_QA_URL`, `DM_OFFLINE_URL`, `DM_PLAYWRIGHT_MODULE` and `DM_CHROMIUM_PATH` (VPS defaults; export them to override). The machine is shared: on a loaded box every screenshot can take 10+ s, so a full run takes an hour or more.

## Writing smokes that stay reliable

Shared helpers live in `tools/qa/lib/qa-common.cjs`:

- `watchErrors(page)`: collects page errors and console errors but ignores favicon, offline-realtime noise and `@fontsource` 403s (Vite refuses font files when `node_modules` is a symlink that points outside the Vite root; the page is fine). Also reports a renderer crash.
- `preloadModules(page, extra)`: loads `GameRuntime`/`devAccess` (plus any `/src/...` paths in `extra`) onto `window.__qaMods` and polls for them. Do not `await import(...)` inside a long `page.evaluate`: on a loaded machine Playwright reports "Resulting promise was garbage collected". Keep evaluates synchronous and put waits on game state in Node.
- `waitGame(page, fn, arg)`: poll a page condition while stepping the game clock (`__cwDebug.advance`), instead of `waitForTimeout`.
- `shot(page, file)`: screenshot with retries. `retryTransient(fn)`: retry only known load-related Playwright errors, never assertions.
- Read expectations from game data (the set table, `AREA_REAGENT_DROPS`, ...) instead of copying numbers; they change when balance does.
- Loot: items do not fly to the player (only gold and shards do; items are picked up within 1.3 m). Use `__cwDebug.lootDrops()` + `teleport()` to walk over them. `reagents-smoke` also pins `Math.random` only for the kill so the real 1% Grave Dust roll succeeds on the first batch.

## Culling diff

`tools/qa/culling-diff.cjs` renders each frame as the game draws it, then again back-to-back with all culling off (every built area group shown, `frustumCulled=false`, tall props forced to cast shadows) and pixel-diffs the two; a second pass turns the occlusion dither off and diffs outside the hero's cut-out; a positive control (hide the hero's area) proves the diff can see. It also prints geometry-only coverage (share of the screen's ground outside the moon's shadow box / inside a hidden area). Env: `DM_QA_AREAS`, `DM_QA_ZOOMS`, `DM_QA_GRID`, `DM_QA_VIEWPORT`, `DM_QA_ENEMIES=1`, `DM_QA_SAVE=1|all`, `DM_QA_OUT`. Exit 1 when any case differs.

# GPU leak smoke

`node tools/qa/gpu-leak-smoke.cjs` (offline preview, `DM_QA_URL`) fights N waves with auto-combat (`DM_QA_WAVES` 12, `DM_QA_WARMUP` 8) and prints `renderer.info.memory` textures/geometries after each wave (area cleared first so live bodies don't count). To find creators, temporarily patch the `Texture` constructor in `node_modules/three/build/three.module.js` to push `{t:this,s:new Error().stack}` into `globalThis.__texLog`, restart vite with `--force`, and run with `DM_QA_TEXLOG=1`.

## Performance budget, pixel metrics, bot playtest (2026-10-02)

Adapted from the ideas in Majid Manzarpour's MIT `threejs-game-skills` (reference notes in `.claude/skills/threejs-graphics-reference/` and `threejs-qa-reference/`; evaluation in `docs/THREEJS-SKILLS-EVAL.md`). All three use an offline dev server (`npx vite --host 127.0.0.1 --port <p> --strictPort`, `DM_QA_URL=http://127.0.0.1:<p>/?offline`) and the usual `DM_PLAYWRIGHT_MODULE` / `DM_CHROMIUM_PATH`.

- `node tools/qa/perf-budget.cjs [--strict]`: the fixed nave fight (same fixture as `fixed-fight-perf.cjs`) on three tiers (`desktop-high`, `desktop-low`, `phone` = Low at 844x390; `DM_QA_TIERS`, `DM_QA_AREAS`, `DM_QA_READS`) and a table of measured vs budget for draw calls, main/shadow triangles, decoded texture MB, JS update ms, assets fetched and `public/` payload. The budgets are the contract in `docs/PERF-BUDGET.md` (keep the `TIERS` constant in the script in step). Exit code is 0 even when over budget (it is, today); `--strict` exits 1 on any over-budget row. JS ms is CPU update cost only and moves with machine load; GPU frame time under SwiftShader is not measured.
- `tools/qa/lib/pixel-metrics.cjs`: colour entropy, dominant-colour share, edge density, luminance mean/contrast and black/blank-frame detection for a screenshot (decoded by Chromium in a blank page; no image library needed). `mobile-shots.cjs` (keys `phone-p-1-hud`, ...) and `zone-tour.cjs` (keys `high-graves-arrival`, `low-nave-fight`, ...) compare every shot with its own baseline in `tools/qa/baselines/pixel-metrics.json` and print `ok` / `new` / `regression` rows (report only; `mobile-shots` fails on a regression only with `DM_STRICT=1`). The art is dark on purpose, so there are no absolute brightness thresholds: a regression is a drop in entropy, edge density or contrast (or a rise in the dominant-colour share) beyond a tolerance, a mean-luminance shift either way, or a black/blank frame. `DM_QA_PIXELS=0` skips the check; `DM_QA_PIXELS_UPDATE=1` rewrites the baselines of the shots taken (do it after an intended look change, with a clean tree: fight shots have live enemies and are noisier than arrival shots).
- `node tools/qa/bot-playtest-smoke.cjs`: a Gravecaller bot plays the Hollow Graves with real WASD / mouse / number-key / right-click / left-click input at two reaction delays (`DM_QA_DELAYS=120,400`, `DM_QA_SECONDS=150`), stepping game time with `__cwDebug.advance`. It reports kills, damage taken, deaths and first-death time per delay, and fails on page errors, a softlock (a move key held for two 12 s windows in a row with under 1 m of movement, a panel or the death overlay stuck up for 12 s, a hero that never rises) or zero kills. Warnings: a single pinned window (the bot nudges itself free) and no kill for 60 s with enemies alive. Report: `report.json` and `bot-<delay>ms.png` in `DM_QA_ARTIFACT_DIR`. A run is a sample, not a balance proof (see `easy-auto-balance.cjs` and `npm run balance`).
